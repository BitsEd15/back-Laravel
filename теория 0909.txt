Роутинг и контроллеры -тема занятия.
Роуты это пути, контроллеры это действия.

Для того, чтобы добавить роут, нужно открыть фвйл web.php
директива use - подключает классы, по указанному пути
use App\Http\Controllers\UserController; - пример, данный путь отражает весь путь до самого файла.
В разработке есть такой арзитектурный стандарт пср, суть в том, чтобы подключать классы по марщруту, соотвествующие названию файла. 
! То есть очень важно, чтобы названия класса и файла совпадали, иначе сайт упадет с ошибкой.

Для того, чтобы в файле, с роутами сработал директива use. В файле контроллера, относящегося к данному роуту необходимо указать namespace. namespace App\Http\Controllers; 
namespace дает понять система классов, где класс находится. То есть классу class UserController мы говорим, 
что ты нахожишься в этом пространстве имен находится. App\Http\Controllers



Какие роуты бывают?
Роуты бывают:
- Route::get
- Route::post
- Route::put
- Route::patch
- Route::delete

REST API — это набор правил, по которым разные программы общаются друг с другом через интернет. 
REST (Representational State Transfer) — это стиль архитектуры, а API (Application Programming Interface) — это интерфейс для взаимодействия программ.
Главные фишки REST:
Использование стандартных HTTP-методов:
GET — получить данные (например, список пользователей).
POST — создать новые данные (добавить пользователя).
PUT (или PATCH) — обновить данные (изменить имя пользователя).
DELETE — удалить данные (удалить пользователя).
Отсутствие состояния (Stateless): каждый запрос от клиента должен содержать всю информацию, необходимую для его выполнения. Сервер не запоминает твои предыдущие запросы. Это как если бы официант каждый раз переспрашивал номер твоего столика — зато это делает систему надежной и простой.
Всё есть ресурс: к данным обращаются через понятные URL-адреса, например, /api/users или /api/orders/123.

В ларавель работа с рест апи ведется по другому. Нам нужен не веб.пхп (он предназанчен для определеня веб роутов). 
Веб роуты - это роуты, результатом работы которого является html. Это значит, что когда мы объявляем веб роут, то в ресурсах, у нас обязательно есть view. В вью есть html.
И контроллер, в ответ на запрос возвращает html. 

А при написании апи, мы не ограничены в формате ответа, можно вернуть html xml json итд. Чтобы работать с более способным форматом, нужно использовать апи роуты. 
Для подключения api.php нужно выполнить команду php artisan install:api. 
use App\Http\Controllers\TestController;
Route::get('/user', [TestController::class, 'sayHello']);
Роут объявляется также как веб роутер. 
http://localhost:8082/api/user - для перехода по апи роуту, обязательно надо дописывать префикс /api 


Роуты делятся на группы.
Все апи роуты будут располежны за url api.
Но иногда бывает нужда группировать роуты, которые мы создаем сами.
Условно говоря, представим ситупци. где у нас есть несколько роутов, которые работа.т именно с пользователем, 
авторизуют, получают пароль, обновляют профиль. То есть работают с юзером.
Соотвественно можно написать свой prefix():
Route::prefix('user')->group(function(){//группируем пользовательские роуты
    Route::get('/get-profile',[TestController::class, 'sayHello']); 
}); - соответсвенно, внутри безымянной функции можно перечислять неограниченное количество роутов и они все будут с нужным префиксом.

Другой плюс данного подхода, это CRUD. CREAT READ UPDATE DELETE.
По сути это весь спектр доступных методов. Можно запись создать, прочитать, обновить, удалить. 
(Если кто то говорит, напиши мне круд. Один енд пойнт для создания, по одному енд пойнт для получения, редактирования, удаления созданного)
Пример CRUD: (есть вопрос по контроллеру)
Route::prefix('crud')->group(function(){
    Route::get('/',[TestController::class, 'sayHello']);
    Route::post('/',[TestController::class, 'sayHello']);
    Route::put('/',[TestController::class, 'sayHello']);
    Route::delete('/',[TestController::class, 'sayHello']);
});
 


Передача параметров в контроллере. 
Когда есть чтение при помощи гет без уточнения, то чиитется сипсок.
Чтобы прочитать конкретный элемент, обычно передается puff параметр, того, что мы хотим прочитать. 
public function readByID( int $id)
    {
       return response()->json([
        'succes'=> true,
        'action'=> 'readByID',
       ]);
    }
    Route::get('/{id}',[TestController::class, 'readByID']); - {id} - это puff параметр


CRUD методы, можно создать с помощью php artisan  make:controller TestController --resource
Создается контроллер, и он уже бывает заполнен методами для круда.
